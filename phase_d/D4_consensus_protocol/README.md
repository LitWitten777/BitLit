# D4 — End-to-end consensus protocol on 100 nodes (Python) · critical

**Mission.** Build the protocol half of the Phase D goal: a simulated network
of at least 100 nodes whose ledger is checked by geometry alone. Planted forks
must be detected and localized, there must be no false alarms, and the
witness rule must leave no blind spots.

**Kind:** Python. **Package:** `d4_protocol`. **Amendment IDs:** FA-010 –
FA-019.

## Read first (read-only)

* `foundation/ws3_consensus/` (README: blind spots, equivocation, "order
  matters"; `consensus_check`, `merge_events`, `event_graph.py`).
* `foundation/contracts/` v1.1.0 (`Event`, `ConsensusReport.blind_spots`).
* `foundation/ws1_geometry/`, `foundation/ws2_gauge/` (groups, `bridges`,
  `components`), `foundation/ws7_benchmarks/` (harness, scale limits).
* `QBX/Formal/MultiEdgeFork.lean` (F6–F6c, proved): the theorems your
  scenarios demonstrate.

## Deliverables

1. **Network model** (`d4_protocol/network.py`): nodes addressed in
   `Q_n □ T^k_m` with at least 100 vertices (e.g. `Q_2 □ T²_5` = 100 or
   `T²_10`). Messages travel along address-space edges in rounds; each message
   is an `Event(src, dst, transport)` with a **non-abelian** transport group by
   default (`PermGroup`, `MatrixGroupGL`), because state updates do not
   commute.
2. **Witness rule** (`d4_protocol/witness.py`): a local rule that makes every
   event lie on a cycle. Examples: each event is countersigned along a second,
   disjoint path; or a node only finalises an event after it closes a short
   loop. Prove in `docs/` (on paper) or test exhaustively that it yields a
   2-edge-connected event graph, so `report.blind_spots == []`. Measure the
   message overhead.
3. **Edge connectivity λ** (`d4_protocol/connectivity.py`): exact λ of the
   event graph (max-flow or Stoer–Wagner, pure Python), cross-checked against
   brute force on small graphs. This is the guaranteed detection radius from
   F6a.
4. **Scenarios** (`d4_protocol/scenarios.py`): honest run; single changed
   event; equivocation (two conflicting events on one transition, in either
   direction); coordinated fork on fewer than λ events; fork on an entire
   minimum edge cut (must be **undetected**, demonstrating F6c); witness rule
   switched off (forks on blind spots undetected, but reported in
   `blind_spots`); reordering of non-commuting updates (detected with a
   non-abelian group, missed with `CyclicGroup`).
5. **Localization:** `consensus_check` names the fork, and for single forks
   and equivocations the planted edge is on the reported loop. Measure this.
6. **Attack catalogue** (`docs/ATTACKS.md`): each attack, its expected
   outcome by theorem (F5, F6a, F6c, equivocation), and the measured outcome.
   Find any case where implementation and theory disagree and report it.
   Check `consensus_check` only through the frozen contract.
7. **Report** (`docs/REPORT.md`, generated by `python3 -m d4_protocol`): 1000
   trials per scenario on ≥ 100 nodes, with detection rate, localization rate,
   false-alarm rate, λ distribution and runtime.

## Done when

* For the 1000-trial runs: detection 100% for single forks, equivocations and
  forks on fewer than λ events with the witness rule on; false alarms 0%.
  Every number in `REPORT.md` is reproducible from a fixed seed.
* `tests/test_d4_*.py` pass in under 60 s (keep large runs out of the tests).

## Out of scope

Real cryptographic signatures (Phase E); networking or timing faults beyond
message loss; changes to `consensus_check` itself (propose them under
`integration/`).
